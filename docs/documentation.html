YourDailyPulse Developer Guide

This document provides a complete guide for setting up, configuring, deploying, and maintaining the Hybrid Firebase/Python version of YourDailyPulse.

1. Overview

YourDailyPulse is a robust hybrid system combining a user-friendly Frontend (Web App) with a powerful Backend (Python Bot).

Key Features

  • Hybrid Architecture: A static Web App (GitHub Pages) serves as the user interface, while a Python backend executes logic based on data in Cloud Firestore.
  • Self-Service: Users sign up, verify emails, and configure their subscriptions/timezones via the Web App.
  • Config is King: Operational parameters are defined in config.json, but user data lives dynamically in Firestore.
  • Multi-Environment Support: Can run "Serverless" via GitHub Actions or as a "Service" via Render.

2.2. Execution Flow: GitHub Actions (Serverless)

This is the default mode. It uses run_once.py triggered by a CRON job. Ideal for keeping costs at zero.

2.3. Execution Flow: Render/Heroku (Service)

This mode uses main.py. It runs 24/7, has an internal scheduler, and a web server for health checks.

3. Initial Setup

3.1. Firebase Setup (Crucial)

This is the heart of the new system.

  1. Create a project at Firebase Console.
  2. Authentication: Enable "Email/Password" provider.
  3. Firestore Database: Create a database. Set rules to allow users to read/write only their own documents.
  4. Service Account: Generate a new private key (JSON) in Project Settings > Service Accounts. Rename it to credentials.json.
  5. Web App Config: Register a Web App in Firebase settings. Copy the config object to `webapp/assets/js/firebase-config.js`.

3.2. Other API Keys

Obtain these for the backend:

  • Telegram: Bot Token via @BotFather.
  • Groq: For LLM generation.
  • Sentry: For monitoring (DSN URL).
  • OpenWeatherMap & Unsplash: Optional but recommended.

4. Configuration & Database

4.1. Data Flow Diagram

Understanding where data comes from is key to customization.

4.2. Firestore (User Config)

User data is stored in the `users` collection. Each document ID is the User UID.

{
  "email": "user@example.com",
  "timezone": "Europe/Bratislava",
  "channels": [{ "platform": "telegram", "identifier": "123456" }],
  "subscriptions": {
    "time07": [{ "theme": "morning_briefing_sk", "days": [0,1,2,3,4,5,6] }]
  },
  "weather": { "locations": [{ "location": "Bratislava,SK" }] }
}

5. Local Testing

Always test your backend logic locally before pushing.

  1. Environment: 
    python -m venv .venv
source .venv/bin/activate  # or .venv\Scripts\activate
pip install -r requirements.txt
  2. Secrets: Ensure .env and credentials.json are in the root folder.
  3. Run a Job:
    Use `run_once.py` to simulate a scheduled run.
    # Run logic for 'time07' for a specific user email
python run_once.py time07 users test@example.com force
    (The `force` flag ignores cache and regenerates content.)

6. Deployment

6.1. Backend (GitHub Actions)

  1. Upload code to GitHub.
  2. In Repo Settings > Secrets, add your env variables (`GROQ_API_KEY`, `TELEGRAM_BOT_TOKEN`, etc.).
  3. Add `GCP_SA_KEY` secret containing the text content of `credentials.json`.
  4. The workflow in `.github/workflows/scheduler.yml` will start automatically.

6.2. Frontend (GitHub Pages)

  1. Ensure your `docs/index.html` contains the redirection logic to your Firebase Web App URL.
  2. Go to Repo Settings > Pages.
  3. Set Source to `main` branch and folder `/docs`.

7. Management & Tools

The project includes `tools.py` for admin tasks.

Database Backups

Since users are now in Firestore, backing them up is critical.

# Backup Firestore users to a local JSON file
python tools.py backup_firestore

# Restore users from a backup file (WARNING: Overwrites data)
python tools.py restore_firestore backups/firestore_users_backup_....json

Content Management

# Download all Google Sheets for local backup
python tools.py download_sheets ./backups

8. Extending the Bot

Adding a new theme requires changes in both Backend and Frontend.

  1. Backend:
    • Create a handler in src/handlers/.
    • Register it in `core.py` mapping.
    • Add config entry in `config.json`.
  2. Frontend:
    • Add theme definition to `webapp/assets/js/themes-config.js`.
    • Add description/images to `webapp/assets/js/theme-details.js`.
    • Add translation strings to `translations.js`.
